# AGENTS.md — правила работы с проектом и функциональный контракт

Этот файл — источник истины о поведении сервиса. Любой агент или разработчик,
меняющий код, обязан прочитать его до начала работы и обновить его, если
поведение меняется **осознанно и с согласия владельца**.

## Обязательные правила изменений

1. После **каждого** изменения запускать:
   ```bash
   npm run typecheck && npm test && npm run build
   ```
   Изменение не считается готовым, пока все три команды не проходят.
2. **Нельзя удалять, ослаблять или «подгонять» существующие поведенческие тесты**
   (`src/**/__tests__/**`) без явного разрешения владельца проекта. Если тест
   падает — чинится код, а не тест. Если поведение меняется по решению
   владельца — тест меняется вместе с описанием ниже, в том же коммите.
3. Любая новая функция добавляется **вместе с тестами**, которые её фиксируют.
4. При рефакторинге UI сохраняются все пункты контракта ниже (они покрыты
   тестами в `src/__tests__/App.test.tsx`).
5. Коммиты — по Conventional Commits (`feat:`, `fix:`, `test:`, `chore:` …),
   проверяются commitlint (хук `commit-msg`). Хук `pre-commit` запускает
   `npm run typecheck && npm test`. Не обходить хуки через `--no-verify`.
6. Не пушить и не создавать релизы вручную — релизы делает release-please.

## Функциональный контракт

### Загрузка данных
- Три слота CSV: **Резюме HH** (`resume`, `HH`), **Вакансии HH** (`vacancy`, `HH`),
  **Вакансии Getmatch** (`vacancy`, `GM`). Файл выбирается кликом по карточке
  (input с `aria-label` = название слота, `multiple`) или перетаскивается на неё.
- Дополнительная зона «+ Перетащите ещё CSV или выберите файл»: тип по
  умолчанию определяется по имени (`detectSlot`: res/resume/cv/резюм → резюме HH;
  gm/getmatch → Getmatch; иначе вакансии HH) или выбирается вручную.
- Разбор — PapaParse, `header: true`, пустые строки пропускаются.
- Каждая загрузка **добавляет** точки (накопление); карточка слота показывает
  имена файлов, число точек и ✓. «Очистить данные» удаляет все точки.
- Счётчик «Загружено точек: N (после фильтров: M)».
- Дата загрузки (`uploadDate`, ISO) проставляется автоматически; в шапке —
  «Данные от <дата>» или «Данные не загружены».

### Нормализация (`src/lib/normalizer.ts`)
- Алиасы колонок: зарплата `ЗП` / `зп` / `salary`; должность `должность` /
  `вакансия` / `position` (иначе `''`); компания `Компания` / `компания` /
  `company` (пусто → `undefined`); город `город` / `city` (пусто → `undefined`);
  индекс `индекс` / `index` / `уникальность` (иначе случайный).
- Дедупликация: `уникальность` (или `count`) > 1 → строка пропускается;
  повтор индекса в рамках одного файла → пропускается.
- Валюта по символу (приоритет `$` → `€` → `₸`, иначе `₽`): `$` ×90, `€` ×100,
  `₸` ×0,2, `₽` ×1.
- Gross (`до вычета`, `gross`, `до налогов`, регистр не важен) → ×0,87, но
  только если нет net-маркера (`на руки`, `net`). Итог округляется до рубля.
- Числа: регэксп `\d[\d\s]*(?:,\d+)?`, пробелы внутри числа убираются,
  десятичная запятая; числа `<= 100` игнорируются. Нет чисел → строка пропускается.
- Каждое число (оба конца вилки) — отдельная точка, `id = ${index}-${i}`.

### Бины и перцентили (`src/lib/binning.ts`)
- `createBins(points, step, maxSalary = 600000)`: бины `[from, to)` от 0 до
  `maxSalary`, подпись `${from/1000}–${to/1000}т`; `vacancyCount`, `resumeCount`;
  `vacancyPct`/`resumePct` — доля от **всех** точек своего типа (знаменатель
  минимум 1 → без NaN); перцентили 0.1…0.9 внутри бина.
- Перцентиль — линейная интерполяция: `idx = (n-1)·p`; пустой массив → 0.
- `computeGradeStats(points, ranges, percentiles)`: точки (вакансии + резюме)
  в `[min, max)`, `count`, `values` по перцентилям; пустой грейд → нули.

### Фильтры и параметры
- Город, компания, должность — подстрока, без учёта регистра; при заданном
  фильтре точки без значения поля отбрасываются.
- Источник: Все / HH / Getmatch.
- Шаг бина: 10 / 20 / 50 тыс. ₽ (по умолчанию 10 тыс.); уровни внутри грейда
  1 / 3 / 4 / 5 (по умолчанию 3). Переключатели — кнопки с `aria-pressed`.

### Грейды и границы
- По умолчанию: Intern 0–80 000, Junior 80 000–150 000, Middle 150 000–250 000,
  Senior 250 000–400 000, Lead 400 000–700 000. Грейды всегда смежные.
- Уровни: 1 → [0.5]; 3 → [0.15, 0.5, 0.85]; 4 → [0.15, 0.35, 0.65, 0.85];
  5 → [0.1, 0.3, 0.5, 0.7, 0.9].
- **Границы меняются только перетаскиванием 6 ручек на графике** (`role="slider"`):
  0 — нижняя граница Intern, 1…4 — между грейдами, 5 — верхняя граница Lead.
  Указатель (pointerdown на ручке + pointermove/pointerup на window) и клавиши
  ← → (±5 000 ₽). Привязка к 5 000 ₽, минимальная ширина грейда 10 000 ₽,
  соседей пересечь нельзя, нижняя граница ≥ 0, верхняя ≤ 1 000 000 (мышью — до
  края шкалы). **Числовых полей для границ нет** — это требование владельца.
- Во время перетаскивания над ручкой показывается значение (`bottom: calc(100% + 6px)`).
- «Сбросить границы» возвращает значения по умолчанию.

### График
- `createBins(filtered, step, chartMax)`, `chartMax = max(700 000, Lead.max)`.
- Вакансии `#4f46e5`, резюме `#c7d2fe`; пунктирные медианы вакансий и резюме;
  подсказка по бину (диапазон, количество и доля); цветные зоны грейдов строго
  по `[min, max)` на линейной шкале; области вне грейдов затемнены.
- Пустые состояния: «Загрузите CSV-файлы слева…» / «Под выбранные фильтры не
  попала ни одна точка» — ручки и лестница остаются интерактивными.

### Лестница грейдов
- На той же горизонтальной шкале, что и гистограмма. Слева цвет, название,
  «min – max · N», в центре полоса от первого до последнего перцентиля уровня
  (для 1 уровня — только риска P50), промежуточные уровни — светлые риски,
  P50 — тёмная риска; справа крупная медиана грейда и значения уровней
  (точные значения — в `title`). Пустой грейд — «нет данных».

### KPI (по отфильтрованным точкам в `[grades[0].min, grades[last].max)`)
- Точек в грейдах; Вакансии (HH / Getmatch); Резюме; Самый массовый грейд
  (при равенстве — первый, с N и медианой); Разрыв ожиданий =
  медиана вакансий / медиана резюме − 1 (нет данных → «—»).

### Экспорт CSV
- Кнопка «Экспорт CSV»: UTF-8 с BOM, разделитель `;`, экранирование кавычек.
  Блоки: фильтры, итоги, таблица грейдов (От, До, N, Вакансий, Резюме,
  Медиана, перцентили уровней), отфильтрованные точки.

### Версия
- SemVer, `package.json` → `__APP_VERSION__` (Vite `define`), в UI бейдж
  `v{версия}`, подсказка `commit {sha}` (`__APP_COMMIT__`).
- Conventional Commits, CHANGELOG.md (Keep a Changelog) и теги `vX.Y.Z`

- `src/lib/__tests__/normalizer.test.ts`, `binning.test.ts`, `grades.test.ts`,
  `stats-export.test.ts` — бизнес-логика; `src/__tests__/App.test.tsx` — пользовательские сценарии UI.
