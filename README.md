# Salary Analytics App

Клиентский сервис аналитики зарплат по данным вакансий и резюме с HH.ru и Getmatch.

## Функционал

- Загрузка CSV в три слота (резюме HH, вакансии HH, вакансии Getmatch): выбор файла или drag-and-drop на карточку; дополнительная зона с автоопределением типа по имени файла или ручным выбором; накопление загрузок; «Очистить данные»
- Дедупликация по индексу уникальности
- Нормализация зарплат в net RUB (курсы $ = 90, € = 100, ₸ = 0.2; gross → net −13%)
- Оба конца вилки становятся отдельными точками
- Бины с настраиваемым шагом (10/20/50 тыс. ₽), шкала графика покрывает весь диапазон грейдов (от 0 до max(700 тыс., верхняя граница Lead))
- Перцентили внутри бинов и грейдов (линейная интерполяция)
- Грейды Intern…Lead, уровни внутри грейда 1/3/4/5 (P50; P15/P50/P85; P15/P35/P65/P85; P10…P90)
- **Границы грейдов настраиваются только перетаскиванием 6 ручек над графиком** (мышь/тач или стрелки ← → с шагом 5 000 ₽, минимальная ширина грейда 10 000 ₽); изменение сразу пересчитывает лестницу грейдов, N и KPI; «Сбросить границы»
- Гистограмма: вакансии ярче, резюме светлее, пунктир медиан, подсказка по бину, зоны грейдов точно по границам
- Лестница грейдов: полоса перцентилей на общей шкале с графиком, медиана и значения уровней
- KPI: точки в грейдах, вакансии (HH/Getmatch), резюме, самый массовый грейд, разрыв ожиданий
- Фильтры: город, компания, поиск по должности, источник (Все/HH/Getmatch)
- Экспорт CSV (UTF-8 с BOM, «;»): фильтры, итоги, таблица грейдов и отфильтрованные точки
- Дата загрузки/парсинга добавляется автоматически; версия приложения в шапке

## Разработка

```bash
npm install
npm run dev
npm test            # автотесты (Vitest)
npm run typecheck   # проверка типов
npm run build
```

Перед изменениями прочитайте [AGENTS.md](AGENTS.md) — там функциональный контракт и правила защиты от регрессий.

## Деплой на GitHub Pages

Соберите и запуште в ветку `gh-pages` или используйте GitHub Actions (см. `.github/workflows/deploy.yml`).

Base path настроен под `/salary-analytics-app/`.

## Версионирование и релизы

- **SemVer** начиная с `0.1.0`. Пока версия `0.x`: `feat` → minor (`0.1.0 → 0.2.0`), `fix` → patch, ломающие изменения (`feat!:` / `BREAKING CHANGE:`) тоже → minor. Выход в `1.0.0` — осознанное решение, когда API/данные стабилизируются.
- **Conventional Commits** (`feat:`, `fix:`, `refactor:`, `docs:`, `chore:` …). Проверяются локально хуком husky + commitlint и в CI на каждом PR.
- **Теги**: `vX.Y.Z` на коммите релиза в `main`, к каждому — GitHub Release.
- **CHANGELOG.md** в формате Keep a Changelog, пишется автоматически.
- **release-please** (`.github/workflows/release-please.yml`): после push в `main` открывает/обновляет Release PR с bump версии и changelog. Мерж Release PR → тег + GitHub Release; деплой на Pages идёт обычным `deploy.yml`.
- Версия показывается в шапке приложения (`__APP_VERSION__` из `package.json` через `define` в `vite.config.ts`), в подсказке — короткий SHA сборки.

```bash
npm run typecheck   # проверка типов
git commit -m "feat: перетаскивание границ грейдов на графике"
```
