# AGENTS.md — правила работы с проектом и функциональный контракт

Этот файл — источник истины о поведении сервиса. Любой агент или разработчик,
меняющий код, обязан прочитать его до начала работы и обновить его, если
поведение меняется **осознанно и с согласия владельца**.

## Обязательные правила изменений

1. После **каждого** изменения запускать:
   ```bash
   npm run typecheck && npm test && npm run build
   ```
   Изменение не считается готовым, пока все три команды не проходят.
2. **Нельзя удалять, ослаблять или «подгонять» существующие поведенческие тесты**
   (`src/**/__tests__/**`) без явного разрешения владельца проекта. Если тест
   падает — чинится код, а не тест. Если поведение меняется по решению
   владельца — тест меняется вместе с описанием ниже, в том же коммите.
3. Любая новая функция добавляется **вместе с тестами**, которые её фиксируют.
4. При рефакторинге UI сохраняются все пункты контракта ниже (они покрыты
   тестами в `src/__tests__/App.test.tsx`).
5. Коммиты — по Conventional Commits (`feat:`, `fix:`, `test:`, `chore:` …),
   проверяются commitlint (хук `commit-msg`). Хук `pre-commit` запускает
   `npm run typecheck && npm test`. Не обходить хуки через `--no-verify`.
6. Не пушить и не создавать релизы вручную — релизы делает release-please.

## Функциональный контракт

### Загрузка данных
- Три типа CSV: **Резюме HH** (`resume`, `HH`), **Вакансии HH** (`vacancy`, `HH`),
  **Вакансии Getmatch** (`vacancy`, `GM`). Разбор — PapaParse, `header: true`,
  пустые строки пропускаются.
- Каждая загрузка **добавляет** точки к уже загруженным (накопление).
- Дата загрузки (`uploadDate`, ISO) проставляется автоматически.

### Нормализация (`src/lib/normalizer.ts`)
- Алиасы колонок: зарплата `ЗП` / `зп` / `salary`; должность `должность` /
  `вакансия` / `position` (иначе `''`); компания `Компания` / `компания` /
  `company` (пусто → `undefined`); город `город` / `city` (пусто → `undefined`);
  индекс `индекс` / `index` / `уникальность` (иначе случайный).
- Дедупликация: `уникальность` (или `count`) > 1 → строка пропускается;
  повтор индекса в рамках одного файла → пропускается.
- Валюта по символу (приоритет `$` → `€` → `₸`, иначе `₽`): `$` ×90, `€` ×100,
  `₸` ×0,2, `₽` ×1.
- Gross (`до вычета`, `gross`, `до налогов`, регистр не важен) → ×0,87, но
  только если нет net-маркера (`на руки`, `net`). Итог округляется до рубля.
- Числа: регэксп `\d[\d\s]*(?:,\d+)?`, пробелы внутри числа убираются,
  десятичная запятая; числа `<= 100` игнорируются. Нет чисел → строка пропускается.
- Каждое число (оба конца вилки) — отдельная точка, `id = ${index}-${i}`.

### Бины и перцентили (`src/lib/binning.ts`)
- `createBins(points, step, maxSalary = 600000)`: бины `[from, to)` от 0 до
  `maxSalary`, подпись `${from/1000}–${to/1000}т`; `vacancyCount`, `resumeCount`;
  `vacancyPct`/`resumePct` — доля от **всех** точек своего типа (знаменатель
  минимум 1 → без NaN); перцентили 0.1…0.9 внутри бина.
- Перцентиль — линейная интерполяция: `idx = (n-1)·p`; пустой массив → 0.
- `computeGradeStats(points, ranges, percentiles)`: точки (вакансии + резюме)
  в `[min, max)`, `count`, `values` по перцентилям; пустой грейд → нули.

### Фильтры
- Город, компания, должность — подстрока, без учёта регистра; при заданном
  фильтре точки без значения поля отбрасываются.
- Шаг бина: 10 / 20 / 50 тыс. ₽ (по умолчанию 10 тыс.).

### Грейды
- По умолчанию: Intern 0–80 000, Junior 80 000–150 000, Middle 150 000–250 000,
  Senior 250 000–400 000, Lead 400 000–700 000.
- Уровни внутри грейда: 1 → [0.5]; 3 → [0.15, 0.5, 0.85] (по умолчанию);
  4 → [0.15, 0.35, 0.65, 0.85]; 5 → [0.1, 0.3, 0.5, 0.7, 0.9].
- Границы грейдов редактируются пользователем и пересчитывают N и перцентили.

### Версия
- SemVer, `package.json` → `__APP_VERSION__` (Vite `define`), в UI бейдж
  `v{версия}`, подсказка `commit {sha}` (`__APP_COMMIT__`).
- Conventional Commits, CHANGELOG.md (Keep a Changelog) и теги `vX.Y.Z`
  ведёт release-please.

## Тесты
- `src/lib/__tests__/normalizer.test.ts`, `src/lib/__tests__/binning.test.ts` —
  бизнес-логика; `src/__tests__/App.test.tsx` — пользовательские сценарии UI.
- Vitest + jsdom + Testing Library; `npm test` (однократно), `npm run test:watch`.
- CI (`.github/workflows/ci.yml`) на PR и push в `main`: typecheck, test, build;
  commitlint на PR. Деплой (`deploy.yml`) тоже прогоняет typecheck и test.
